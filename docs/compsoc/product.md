# CompSoc: product

PeatPulse compares historical burn prediction on peatland: weather alone versus weather plus additional observations of peat condition. The [expanded local experiment](peatpulse-expanded-results.md) now tests three models against directly ranked Copernicus FWI using five-fold grouped validation. The strongest weather + CEMS model alerts on 6 of 25 mapped burn groups, versus 2 for raw FWI at the same budget. Adding radar alerts on 3 groups and does not improve the trained weather model. The current evidence supports a retrospective peatland-burn ranking prototype; live wildfire warning remains unvalidated. The [first 45-cell experiment](peatpulse-training.md) is preserved separately.

The [four-family algorithm comparison](peatpulse-algorithm-comparison.md) confirms Random Forest as the strongest tested model at the fixed daily alert budget. Extra Trees improves overall ranking scores; the radar addition does not improve the group-catch count for any tested family.

- Make the story page the presentation deck the user presents from, in their twelve sections: what peatlands are and why burning them matters, Scotland's response, where PeatPulse comes in, the daily ranking, the result against FWI, how we built it (data, algorithms, testing), a worked example, the report and the GitHub close, because the user will present with it. **3 October 2026.**
- Keep the story slides light, with little text and simple figures only: the 3% squares, the Scotland maps, a ranked-squares strip, the testing rounds, the budget chart and the example rankings. Decorative illustrations, icons on the government and data-source slides, and square-by-square result animations were removed, because the user found them too much. **3 October 2026.**
- Reduce the overall page scale and report text width after the user found the site too zoomed in, because the report fonts, cover image and text column should fit more comfortably on screen. **3 October 2026.**
- Create a fresh PeatPulse demo website and develop it one agreed step at a time, because the user wants a new presentation experience rather than reuse of the existing data explorer. **3 October 2026.**
- Start the website with a subdued peatland background and two choices: “Read the story” opens the presentation, while “Read the report” opens the technical report. Remove the report’s print button and link the source section to GitHub. **3 October 2026.**
- Let the user review website views themselves and stop further automated visual checks for this slice, because they explicitly asked to build and move on. **3 October 2026.**
- Use the same simple, concrete language as the model explanations, with standalone headings and no decorative text above or supporting subtext below them, because the user explicitly rejects that heading pattern. **3 October 2026.**
- Avoid em dashes throughout CompSoc copy, because the user asked to remove them everywhere. **3 October 2026.**
- Open with the carbon-emissions problem and its importance to Scotland before introducing peatland fire-risk ranking, over a wet peatland and forest background with an almost three-dimensional feel, because the user wants the audience to understand the environmental stakes first; exact copy and statistics remain under discussion. **3 October 2026.**
- Test additional algorithm families locally against the existing Random Forest and FWI results, because the user wants to see whether another learning method performs better; keep this work uncommitted and unpushed. **3 October 2026.**
- Include ordinary accuracy in the presentation alongside burn detection and the always-no-burn reference, because the user wants the familiar accuracy figure while retaining an interpretable comparison. **3 October 2026.**
- Benchmark PeatPulse against directly ranked Copernicus FWI on identical dates, candidate cells and alert budgets, and improve the models using training-only tuning, because the user wants a strong measured result for a clearly defined satellite-burn prediction problem. **3 October 2026.**
- Retain every discovered burned 1 km cell as a separate location example, while keeping all cells of the same fire together during validation, because the user wants to learn where a fire spreads without treating those cells as independent events. **3 October 2026.**
- Use grouped cross-validation instead of a separate validation year for the expanded small dataset, keeping each event and linked comparison cells together, because the user wants to make better use of limited independent fire examples without leaking repeated rows between folds. **3 October 2026.**
- Expand the dataset with more independent historical burn events and comparable non-burning observations, reserving entire events for evaluation, because the first sample has too few positive examples to test the added value of radar. **3 October 2026.**
- Train the first models on the local machine using the available dataset now, because the user wants a working local model within the remaining hackathon time. **3 October 2026.**
- Prepare both a provisional satellite-detected burning target and a separately verified wildfire target, with explicit unknowns, because the user approved both outputs for the existing locations and dates. **3 October 2026.**
- Compare weather-only predictions with predictions using additional peat/environmental observations against the same historical actual-fire outcome, because the user wants to demonstrate whether the extra tracking improves advance fire prediction. **3 October 2026.**
- Use the Climate Engine Earth Engine CEMS Fire Daily collection for historical fire-weather indices, because it exposes the Copernicus-derived indices needed for the weather baseline and reads successfully with the team's Earth Engine project. **3 October 2026.**
- Organize the plan around the finished deliverable, distinctive contribution and success evidence rather than a sequence of progressively expanded prototypes, so both teammates know the intended submission directly. **3 October 2026.**
- Show only held-out FWI and weather + CEMS alerts, coloring each cell by which method selected it more often under the shared daily budget. Omit historical burn markers and show the 2/25 and 6/25 burn-group catch counts, because overlapping full-frequency heatmaps hid the spatial differences. **3 October 2026.**
- Download and visually audit the matched datasets before model fitting, including feature correlations and a proposed input list, because the user wants to establish data viability and avoid redundant inputs. **3 October 2026.**
